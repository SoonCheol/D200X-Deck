# DeckForge 1.1 — 물리 키 Key Down / Key Up 아이콘 적용 예외·처리 기준 (2026-11-17)

> **상태:** 설계 및 코드 근거 정리만 완료. **기능 구현·실기 검증 아님.** 현재 이 문서는 후속 개발을 위한 정책 기록이며, 기존 프로젝트의 동작을 바꾸지 않는다.
>

## 1. 확정된 사용자 요구

- **기준은 D200X 실물 물리 버튼의 Key Down(누름) 및 Key Up(놓음)** 이다. DeckForge 대표 아이콘의 마우스 누르기는 *명령을 실행하지 않는 시각적 시뮬레이션*일 뿐이다.
- **일반 무상태 액션:** `Key Up`=기본 아이콘, `Key Down`=누르는 동안의 아이콘, 놓으면 기본 아이콘 복귀. 기본 이미지와 눌림 이미지가 같으면 기존 축소/복귀 애니메이션을 사용한다.
- **Autodesk Fusion 360 전체 명령:** 전부 위 Key Down/Up 아이콘 방식 적용. Fusion 명령 실행 완료/취소 이벤트를 알아내어 상태를 유지하는 기능은 요청하지 않았으므로 추가하지 않는다. 버튼을 놓으면 Fusion 내 명령 지속 여부와 관계없이 기본 이미지로 돌아간다.
- 상태형 액션의 **실제 상태를 Key Up 이벤트로 덮어쓰지 않는다.**
- 기본/눌림 이미지의 초기값은 동일한 대표 아이콘으로 맞추고, 사용자가 개별로 교체할 수 있게 한다. 기존 프로필, 사용자 아이콘, HA/SDK 설정 보존.
- 아래 분류는 **아이콘 표시 정책**이다. 원래의 액션 실행 타이밍/SDK 전송/장치 제어를 변경하거나 모든 액션에 새로운 Key Up 실행 로직을 강제하지 않는다.

## 2. 일반 방식에서 제외하거나 예외 처리가 필요한 액션

| 구분 | 액션 ID / 범주 | 일반 Key Down/Up 아이콘 2상태 방식의 문제 | 구현 시 규칙 |
|---|---|---|---|
| **적용 제외** | `indicator` (페이지 표시기) | 표시 전용이고 실행할 누름 동작이 없다. | **기본 아이콘 유지**, Key Down/Up 이미지 편집 항목을 표시하지 않음. |
| **적용 제외/시각 제한** | 와이드 정보 표시 영역 (특수 D200X 화면 슬롯) | 일반 실행 키와 화면 모드 전환 로직이 다르며 화면 전체 재그리기를 누름 상태로 덮어쓰면 충돌 가능. | 일반 키 아이콘 2상태 적용 제외. 기존 와이드 정보/모드 전환 경로 보존. |
| **상태 우선** | `ha-toggle` 및 HA 상태 제어 SDK 액션 | 실제 Home Assistant 장치 ON/OFF 상태를 나타내므로 Key Up 때 OFF/기본으로 되돌리면 거짓 상태가 된다. | 실제 장치 상태 아이콘 유지. 누름 피드백은 시각 효과로 분리하되 상태 아이콘을 바꾸지 않음. |
| **상태 우선** | `sd-plugin` 중 **상태를 제공하는** SDK 플러그인 | SDK가 `setState`/`setImage` 등의 업데이트를 제공할 수 있어 Key Up 기본 아이콘 강제가 플러그인 표시를 덮어쓴다. | 플러그인 상태/이미지 우선. **단, Fusion의 전체 명령은 사용자 지정 예외로 무상태 Key Down/Up 정책 적용**. 모든 SDK 플러그인을 한 부류로 묶지 말 것. |
| **상태 우선** | `multi-switch` (다중 동작 스위치) | 실행할 때 상태 1/2가 바뀐다. Key Up만으로 초기 이미지 복귀하면 활성 상태가 보이지 않는다. | 상태 1/2 이미지 유지; 누름 피드백은 별도 오버레이/효과로 처리. |
| **상태 우선/추가 설계** | `hotkey-switch` (단축키 전환) | 내부적으로 1번/2번 단축키가 교대 실행된다. 이 값을 시각화할 경우 기본 아이콘으로 무조건 복귀시키면 실제 다음 실행 대상이 숨겨진다. | **현재 전환 위치의 시각화는 후속 설계 대상**. 아이콘 상태를 도입한다면 Key Up이 순환 상태를 지우지 않도록 분리. 단순 누름 피드백만 제공하는 기본 정책도 가능하나 상태 의미와 혼동하지 말 것. |
| **진행 상태 우선** | `timer` (타이머) | 동작 중 카운트다운·재누름 취소를 표시한다. Key Up 갱신이 시간 표시를 덮어쓰면 안 된다. | 타이머 텍스트/실행 상태 유지. 눌림 시 시각 피드백만 적용. |
| **입력 의미 우선** | `logic` (Key Logic) | 눌렀다 떼기·두 번 누르기·길게 누르기 판정에서 Up 이벤트가 실제 명령 판정에 사용된다. | 아이콘 피드백 자체는 가능하지만 기존 Key Down/Up 실행 판정기와 독립적으로 유지. 단순 액션처럼 Up 시 무조건 실행/초기화 로직을 교체하지 말 것. |
| **입력 의미 우선** | `open-app` + `settings.hold`가 `close` 또는 `force` | 버튼 유지 시간으로 프로그램 종료/강제 종료가 결정된다. | 시각 피드백은 가능하되 눌림 시간과 Up 처리/기존 길게 누름 기능 보존. |
| **화면 변경 예외** | `previous`, `next`, `goto`, `profile`, `folder` | Down 즉시 표시 페이지·프로필·폴더가 바뀌어 원래 키가 화면에서 사라질 수 있다. | 원 화면의 피드백은 화면 전환 전까지만, 새 화면에서는 새 슬롯 이미지 즉시 표시. 이전 페이지의 눌림 이미지가 다음 페이지 슬롯에 남지 않게 할 것. |
| **기기 화면 제한** | `sleep` (D200X 화면 잠자기) | 버튼을 누르면서 장치 화면이 잠들 수 있어 눌림 아이콘 자체를 표시할 기회가 없다. | 잠자기 기능 우선. 시각 피드백은 보장하지 않음; 다음 깨우기 입력을 잘못 실행하지 않도록 기존 로직 보존. |

### 분류에 대한 주의

- **엄밀히 '적용 불가'인 일반 키는 표시 전용 `indicator` 등 일부**이고, 나머지는 대부분 *버튼 눌림 피드백은 가능하지만 상태 이미지까지 무조건 Up으로 초기화하면 안 되는 경우*다.
- `multi`(다중 동작), `random`(무작위 동작), 대부분 일반 미디어/시스템 액션은 **원칙적으로 기본/눌림 아이콘 적용 가능**하다. 긴 작업이 눌렀다 뗀 뒤 계속 실행되어도 눌림 이미지는 Key Up에 복귀한다.
- `system-mute`, `media`의 재생/일시정지 등은 동작 자체가 토글이지만 **현재 코드에서 실제 OS/미디어 상태를 추적해 아이콘을 유지하는지 확인하지 않은 한**, HA와 같은 상태형 이미지 정책을 자동 부여하지 않는다. 향후 상태 추적 기능을 추가할 경우 그때 분류 재검토.
- 와이드 정보 슬롯, 측면 버튼, 노브의 누름/회전은 일반 키 그리드와 입력 경로가 다르다. 실제 지원 범위는 별도 실기 검증 후 확정한다. 노브 회전에 Key Down/Up 아이콘을 임의로 적용하지 않는다.

## 3. 현재 코드에서 확인한 사실 (구현 전 참고)

- `app/streamdeck-editor/editor.js` 처음의 `ORIGINAL_CATALOG`에 액션 ID와 이름이 정의되어 있다. `ACTIONS.set('sd-plugin', ...)`으로 SDK 액션이 추가된다.
- `editor.js`의 `executeHardwareAction()`은 일부 `up` 이벤트를 SDK 플러그인으로 전달하고, Key Logic/길게 누르기용 `open-app`은 Down/Up 모두 실행 판단에 사용한다. 일반 액션은 Up을 받으면 이후 명령 실행을 중단하고 반환한다.
- `editor.js`에서 `multi-switch`는 완료 후 `settings.activeState`를 전환하고, `timer`는 `timerDeadlines`를 이용해 실행 중 타이틀을 표시한다.
- `app/streamdeck-editor/device-sync.js`는 물리 키 누름 피드백용 `pressedKeys`와 약 120ms 지연 해제·축소 렌더링을 이미 사용한다. **이는 별도 기본/눌림 이미지 지정 기능이 구현되었다는 뜻이 아니다.**
- `editor.js`의 `bindSdkStateIcons()`에는 SDK 액션용 OFF/ON 이미지 편집 코드가 있다. 일반 액션에 대응하는 공통 Key Down/Up 편집기를 새로 연결하는 작업은 별도 구현 필요.
- D200X의 표시 동기화는 `device-sync.js`에서 전체 PNG를 재렌더하므로 빠른 Down→Up, 페이지 이동과 늦은 비동기 이미지 응답을 섞었을 때 이전 이미지를 덮어쓰지 않는지 회귀 테스트가 필요하다.

## 4. 후속 구현 체크리스트 (아직 수행하지 않음)

1. 타입별 `iconBehavior` 또는 동등한 비파괴 정책 분류: **momentary**(Fusion 포함 일반 액션), **stateful**(HA/상태형 SDK/다중 동작 스위치), **display-only**, **navigation/special**. 기존 저장 포맷을 강제 변환하지 말 것.
2. momentary 타입에 '기본(Key Up) / 눌림(Key Down)' 아이콘 설정 제공. 기존 사용자 지정 아이콘, SDK OFF/ON, Fusion 자동 아이콘 읽기와 우선순위를 결정하고 테스트.
3. 실제 물리 키 Down/Up에 따라 **DeckForge 그리드·인스펙터 미리보기·D200X 화면**을 일관되게 전환. 일반 액션 누름 시 이미지가 같으면 기존 애니메이션을 사용하되 이중 효과 금지.
4. 인스펙터 대표 이미지 마우스 미리보기는 **실제 액션 실행·SDK keyDown 전송·HA 토글 없이** 순수 시각 시뮬레이션만 실시.
5. 상태형/페이지 이동/고정 키/길게 누르기/빠른 연타와 기존 트레이·노브·HA·Fusion 기능 회귀 검사.
6. 사용자가 **명시적으로 구현·빌드를 지시한 다음에만** 소스 수정 및 빌드. 테스트 결과를 CI/Windows GUI/D200X 실기로 구분 기록.
