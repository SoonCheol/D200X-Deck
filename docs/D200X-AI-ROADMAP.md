## 2단계 — 1.1.44 읽기 전용 환경 조회

- 기존 버전 함수에 inspect 함수 추가, 17개 조회 영역(section): profiles, page, actions, icon_packs, icons, start_apps, running_windows, device, recent_inputs, plugins, plugin_actions, ha, fusion, app_log, folder_log, usb_log, guide. 입력은 설정된 enum·1기반 프로필/페이지/폴더 경로·검색어·offset만 허용.
- 디스크 저장본 조회와 현재 화면 메타데이터를 구분하며 미저장 초안은 전송하지 않음. 페이지 키 목록에는 고정 키 적용과 예약 와이드 위치를 표시하고 노브 설정을 요약. raw 경로, 프로그램 인수, 텍스트 입력 본문, 인증 정보, 플러그인 비공개 설정, 원본 이미지 제외. 사용자 지정 이름 자체에 민감한 내용이 포함될 수 있으므로 명시적 조회 허용, 흔한 비밀 패턴 마스킹 적용(모든 개인정보 자동 제거를 보장하지 않음).
- Windows 조회는 고정된 Get-StartApps / Get-Process 대표 창 조회만 수행, 명령 문자열과 경로를 모델에서 받지 않음. 모든 설치 프로그램·모든 창의 완전한 목록은 아님. SDK는 설치 매니페스트, HA는 기존 내장 REST 설정과 지원 엔티티, Fusion은 기존 로컬 health 기준. 장치/로그는 실제 동작 성공과 구분. 앱/폴더 로그의 전체 원문과 범용 실행 추적 기능은 별도 과제.
- AI 패널에는 질문별 조회 허용, 조회 단계 표시, 응답 완료 시 API 요청 횟수·실제 응답 usage 토큰 합(있을 때만) 표시. 최근 8개 메시지/16,000자, 조회당 최대 3 API 요청·4 함수 호출, 결과 각 12,000자/전체 24,000자, 중복 및 금지 함수 차단, 필터/페이지네이션 및 요청 단위 캐시. 구독 차감량 산정이나 외부 앱 한도 추정 안 함.
- 1단계 사용자 확인: 1.1.43 우클릭 복사/붙여넣기 정상. 응답 도중 중지는 미검증. 2단계에 기존 기능 변경·파일 쓰기·실행 권한 없음.

### 2단계 최소 실기 시험
1. AI 도우미에서 이번 질문의 로컬 정보 조회 허용 체크 후 '프로필 목록과 현재 페이지에 등록된 버튼을 알려 줘'. 실제 저장 화면과 비교, 미저장/폴더 표시 구분.

3. '시작 메뉴에 등록된 메모장 AppID를 찾아 줘', '현재 열린 프로그램의 대표 창 상태를 알려 줘', '아이콘팩과 전등 아이콘을 찾아 줘'. 각 질문에 조회 체크.
4. 필요한 경우 '설치된 플러그인과 HA 내장 연결/Fusion 상태', '최근 프로그램/폴더 열기 로그의 실패 단계를 알려 줘'. SDK 전용 HA와 실제 성공 여부는 별도.
5. 조회 미허용 상태에서 로컬 상태를 묻거나 쓰기/PowerShell 실행을 요구하면 조회/실행하지 않는지 확인. 요청·조회 횟수 및 보고된 토큰 수 확인. 3단계는 사용자 승인 후 시작.

## 3단계 — 1.1.45 승인 기반 기본 버튼 편집

## 4단계 — 1.1.46 고급 편집 및 AI 창 개선

- 조회/변경안 체크 선택은 AI/preferences.json의 두 boolean으로 보존하며 최초 해제. 조회 해제 시 변경안도 해제. 체크 상태가 유지되어도 적용은 사용자 확인이 필요함. Markdown은 별도 라이브러리/네트워크 없이 안전한 텍스트 DOM으로 렌더링. 제목·굵게·기울임·코드·표·목록·인용·구분선 지원, 임의 HTML/이미지 로딩/URL 이동 금지. 스트리밍은 일반 텍스트로 유지하고 완료 시 렌더링.
- propose_advanced의 8종류: folder_keys, folder_page, folder_settings, control, wide, composite, state_design, plugin. page 1기반, folder slot:page 경로, 원래 일반 키 1~13/물리 컨트롤 1~5. 한 질문당 제안 하나, 종류 하나. 고정/예약 슬롯/기존 보호 액션 덮어쓰기 금지. 단일 원자 저장 및 최근 AI 변경 undo 경로 유지.
- 폴더 일반 키 등록/수정/삭제 최대 8개, 중첩 폴더/자동 닫기/페이지 추가. 프로그램 Start AppID 또는 사용자 직접 제공 로컬 경로는 기본 편집 검증 경로 재사용. 폴더 내부 복사/이동 및 복합·노브 안의 프로그램/파일 등록은 미지원. 노브 양방향 및 누르고 회전, 스코프, 자동 대상 및 스택 설정 지원. 와이드 가용 모드 순서/현재 설정. 신규 multi/multi-switch/random/logic은 기본 단계 및 허용 지연만, 기존 복합/SDK 임의 덮어쓰기/중첩 금지.
- 상태 디자인은 기존 UI 지원 키/SDK의 두 상태별 제목·노출·크기·색·굵기·배경·정확한 팩 이미지. SDK OFF/ON 페어는 양쪽 정확한 선택과 실제 동반 아이콘 일치 확인 시 기존 페어 메타데이터 사용. 기본 복합 스위치 전용 stateVisuals·모든 디자인 세부 옵션은 아직 지원하지 않음.
- 내장 HA는 실제 연결 엔티티 검증 후 등록. SDK HA 및 Fusion은 기존 등록 설정에서 검증된 엔티티/명령 템플릿과 설치된 매니페스트가 일치할 때 복제. 사용자 임의 SDK settings/토큰/새 Fusion 명령 추측 불허. inspect plugin_templates는 저장된 템플릿 이름과 ID만 반환. 미등록 명령/SDK 엔티티의 전용 검색·속성 편집은 후속 확장 필요.

### 4단계 최소 실기 확인
1. 체크 하나를 켜고 연속 질문 후 앱 재시작, 체크 유지 확인. 변경안 체크 시 조회도 체크, 조회 해제 시 변경안 해제. 표 및 굵은 제목이 Markdown으로 표시되는지 확인.
2. '노브 1의 회전 조절 대상을 음량으로 설정해 줘', '와이드 화면을 날짜 시간과 노브 정보 모드로 설정해 줘'. 미리보기 적용 후 실제 장치 동작 확인.
3. 기존 덱폴더 경로를 알려 주고 내부 빈 키에 복사 단축키 등록, 폴더 페이지 추가. 일반 빈 키에 Ctrl+C → 200ms 지연 → Ctrl+V 다중 동작 등록. 테스트 문서에서 확인.
4. 기존 일반 또는 SDK 키의 첫 번째/두 번째 제목 설정, 정확한 팩 이름/아이콘 이름으로 상태 아이콘 적용. HA 내장 또는 기존 SDK 템플릿, 기존 Fusion 명령을 빈 키에 등록한 뒤 실제 동작 확인.
5. 변경안 취소, 적용 전 편집 변경 거부 및 최근 AI 변경 되돌리기 확인. 5단계는 사용자 승인 후 시작.
