# D200X 기본 액션 확장·버튼/노브 공통화 계획

> 기준: 2026-11-14 사용자와 합의한 개발 방향. **설계 항목과 실제 구현/실기 검증은 별도**.
> 선행 문서: [D200X-STREAMDECK-ROADMAP.md](D200X-STREAMDECK-ROADMAP.md), `../AGENTS.md`.
> 작업 브랜치: `codex/streamdeck-761-clean-editor`. GitHub 원격 커밋/검증 근거가 없는 작업은 완료라고 쓰지 않는다.

## 변경 불가 원칙

1. Stream Deck 7.6.1 관찰 기반 **기존 24개 기본 Key 액션을 삭제/대체하지 않는다.**
2. D200X 기본 기능은 별도 사용자 플러그인 없이 설치 즉시 사용한다.
3. UI는 승인된 `app/streamdeck-editor/` 레이아웃을 고정하고 필수 속성만 국소적으로 추가한다.
4. `editor-ui → deck-core → ulanzi-driver`를 유지한다. Ulanzi의 기존 UI/속성 편집기를 가져오지 않고 USB/HID 통신만 재사용한다.
5. 버튼·노브에 같은 **action.type/settings**를 저장하고 같은 실행 엔진으로 보낸다. 입력 어댑터만 `press/release/rotate-left/rotate-right` 이벤트로 다르다.
6. 입력 장치별 능력이 다른 기능은 명시적으로 제한한다. 길게 누르기는 해당 하드웨어의 down/up과 시간 경과를 실측 검증할 때만 지원하며 가상의 이벤트를 만들지 않는다.
7. 기존 페이지 이동(한 번 후 할당 해제처럼 보이는 문제), USB 로고 복귀 방지/재연결, 아이콘/글꼴, 전역/페이지별 노브 바인딩을 회귀 방지 대상으로 한다.
8. 기존 24개 액션이 **목록에 존재함**과 **기기에서 실제 실행됨**은 별개다. 새로운 액션도 기능별 실기 확인 전 완료 아님.
9. 독립 PR 병합, `main`/`windows-port` 변경, 플러그인 제작, 로컬 중요 파일 삭제·이동은 별도 지시 없이 하지 않는다.

## D200X 추가 액션 — 노브 시험용 (2026-11-14)

- 기존 24개와 별도 `D200X 추가 액션` 범주: `system-volume`(Windows 음량), `system-mute`(음소거 토글).
- 노브에 음량 액션을 놓으면 회전 조절형으로 전환한다. 누르기 칸에 음소거를 별도 배치하면 **회전=음량, 누름=음소거**로 시험 가능. 기존 누르기 액션은 자동 덮어쓰지 않는다.
- 버튼에는 음량 증가/감소(1·2·5·10) 및 음소거 지정 가능. 기존 Windows 키 전송 재사용. **실제 Windows/D200X 검증 전에는 완료 아님**. P0-B/C 전체 완료를 의미하지 않는다.

## 통합 이벤트·설정 계약 (설계)

- 입력 어댑터: 물리 버튼 `press/release`, 노브 `press/release/rotate(delta)`. 실제 D200X HID에서 지원된 이벤트만 매핑한다.
- 단일 액션: `{type,settings}`; 버튼에서는 `press`에 실행, 조절형 노브에서는 회전 부호에 따른 `delta` 실행. 조절형 액션을 버튼에 등록하면 증가·감소·토글 중 실행할 연산을 사용자가 선택한다.
- 공통 노브 옵션: 한 칸 변화량 `1/2/5/10`(제한·단위는 대상별 적용), `reverseDirection` boolean, 좌/우 미리보기. 기존 바인딩은 `step=1, reverseDirection=false`로 마이그레이션한다.
- 조절기 확장: `page, volume, zoom`은 기존 코드 경로를 이행; `scroll, brightness, timeline, brush`는 각각 백엔드와 가능 범위를 검증한 후 추가한다.
- 회전의 변화량 적용은 노브가 실제로 보낸 이벤트당 수행한다. 장치 보고서가 전달하지 않는 연속 속도·롱프레스 같은 신호를 추정 생성하지 않는다.
- 앱별 단축키는 프로필/앱 매핑으로 정의하되 안전한 가상 키 allowlist 또는 검증된 입력 엔진으로 전달한다. 사용자 문자열을 셸 명령으로 조합하여 실행하지 않는다.
- `volume/zoom`의 기존 구현은 별도 PowerShell 프로세스 호출을 사용한다. 빠른 회전 부하/메시지 순서/지연 및 Windows GUI·D200X 실기 확인 후 최적화한다.
- `device-brightness`는 `ulanzi-driver`를 통한 장치 실제 밝기 명령을 재사용하고, 기존 keepalive가 보고받은 밝기를 일관되게 유지하는지 검사한다.
