- **0단계:** 데이터 호환·실행기 인터페이스 → **1단계:** 다중 동작 순차 실행·Delay·내부 편집 → **2단계:** 다중 동작 스위치 → **3단계:** 무작위 → **4단계:** Key Logic(실제 눌림·뗌 실측 필요) → **5단계:** 폴더·프로필·페이지 → **6단계:** Soundboard/시스템/Stream Deck 나머지 → **7단계:** D200X 확장 기능 회귀 검사. 플러그인은 그 뒤 별도 승인.

## 2026-11-14 실행 테스트·밝기 보호·원본 액션 확장 (코드 단계)

- **안전:** `transport.cjs`의 D200X 버튼/노브 상대 밝기를 **20~100%**로 제한하고, 원본 `brightness` 고정값(최소/낮음/중간/높음/최대)을 20/30/50/75/100%로 연결했다. **20% 실제 시인성은 장치 실측 전 미확인.** 이미 20% 미만인 기기 값을 단순 keepalive가 그대로 유지하는 기존 정책은 별개다.
- **미리 실행:** 버튼 선택 후 `▶ 실행 테스트` / 노브 왼쪽·오른쪽·누름 테스트를 기존 물리 이벤트와 동일한 `DeckCore.previewHardwareEvent` 어댑터로 실행. **PC 편집창이 활성화되면 Ctrl+Z 등 전경 앱 대상 키가 편집기 쪽으로 갈 수 있으므로 실제 앱 결과는 실기 검사 필요.** 단축키·텍스트·파일 닫기 같은 영향 있는 동작은 사용자가 버튼을 명시적으로 눌렀을 때만 실행한다.
- **파일 선택 UI:** 물리 버튼/노브 속성에서도 파일/폴더 선택기를 연결한다. 기존 14개 키의 클릭은 여전히 편집용이다.

- **부분 구현 명시:** `timer`의 사운드 알림·화면 카운트다운, `text`의 진정한 클립보드 붙여넣기 모드(현재 클립보드를 바꾸지 않고 Unicode 직접 입력), `audio-play`의 페이드·출력장치, `open-app`의 길게 누르기 옵션, `website`의 브라우저 직접 선택은 미구현. 실기 재생 호환성/Windows Unicode SendInput/C# 컴파일 여부는 아직 검증되지 않았다.

## 2026-11-14 다각도 재조사에 따른 우선순위 수정 (최신 작업 지침)

**상세 근거:** [D200X-STREAMDECK-RESEARCH-REVIEW-20261114.md](D200X-STREAMDECK-RESEARCH-REVIEW-20261114.md). 기존 P0/P1/P2 진행 기록은 보존하되, 앞으로의 실행 순서는 아래를 우선한다. 이 절은 **조사/계획 갱신이며 코드 구현이나 실기 완료가 아님**.

1. **0단계: 자료형·허용 관계·저장/실행 정책 확정** — 원본 다중 동작은 자기 자신을 중첩할 수 없으므로 무제한 재귀 엔진을 만들지 않는다. `multi`의 순서형 목록, `multi-switch` 상태별 독립 시퀀스, `random` 후보, `logic` 눌림 형태별 3슬롯은 서로 다른 구조로 분리한다. 기존 `children[]` 이관/비손실 저장 테스트 먼저.
2. **1단계: Multi 편집·실행** — 내부 드래그/순서/삭제, 명시적 Delay 항목(ms), 가상 키 누름/뗌 시간과 다음 액션 간격을 분리; 원본 공식 문서 간 수치 불일치(2~100ms vs 2~200ms)를 7.6.1 GUI에서 검증한 뒤 확정. 실행 중 취소/연속 재누름/실패 표시를 별도 기준으로 둔다.
3. **2단계: Multi Action Switch** — 상태 1·2별 시퀀스와 아이콘/제목 연결; 상태 전이 시점과 저장·복원 정책은 원본 실측 후 확정. 단일 토글 `children[]`로 대체 금지.
4. **3단계: Random Action** — 후보 중 1개 선택. 관찰하지 못한 가중치·연속 반복 방지 기능을 UI에 추측 추가하지 않는다.
5. **4단계: Key Logic** — 단일/더블/길게 누르기는 실제 HID down/up 및 시간 구분 검증 뒤 별도로 구현. 복합 액션 안의 Key Logic 또는 그 반대 중첩은 원본 허용 관계 확인 전 보류.
6. **5단계: Folder/Profile/Pinned** — 폴더 깊이·뒤로가기·0~60초 자동 나가기, 페이지 고정 액션의 빈 슬롯 상속·덮어쓰기, 프로필 수동/전경 앱 자동 전환 및 **편집 화면 중 자동 전환 비활성**. 공식 페이지 상한 10개와 현 128개 허용의 충돌은 기존 설정을 자르지 않고 별도 정책 결정 후 수정.
7. **6단계: 24개 속성/엔진 완성 및 P1** — Soundboard 페이드 1~5초/장치 출력, 타이머 사운드, 텍스트 두 모드, Open App 길게 누르기, 관리자 권한 전경 앱 단축키, 마이크/오디오 출력. 신규 EXE의 실제 GUI·하드웨어 테스트 전 완성 판정 금지.

**실사용/공식 자료에서 발견한 필수 시험:** 다중 동작 도중 포커스 이동과 단축키 미수신, 중단 상태에서 재누름, 상태별 아이콘 표시, 프로필 전환 중 페이지 복원, 빠른 노브 회전. Ulanzi 공개 구현은 하드웨어 참고용이지 Stream Deck UI 대체품이 아니다.

- 버튼에는 음량 증가/감소(1·2·5·10) 및 음소거 지정 가능. 기존 Windows 키 전송 재사용. **사용자가 2026-11-14 노브 음량·음소거 실기 정상 작동을 보고함**(독립 로그·스크린샷 없음). P0-B/C 전체 완료를 의미하지 않는다.
- **후속 코드(빌드 보류):** `system-scroll`을 같은 별도 범주에 추가. 세로/가로, 상하/좌우, 변화량 1·2·5·10 선택; 버튼은 누름, 노브는 조절형 회전에서 공통 계획 함수와 Windows 스크롤 IPC를 사용. P0-B 공통화 일부 진전이며 **실제 EXE/Windows/D200X 검증은 미실시**.
- **실행 취소·다시 실행 코드(빌드 보류):** `edit-history`를 기존 24개와 분리한 D200X 추가 액션으로 등록. 버튼 누름에는 Ctrl+Z 또는 Ctrl+Y와 횟수 1·2·5·10 지정; 노브 조절형에서는 왼쪽=취소, 오른쪽=다시 실행(반전 가능). 기존 공통 플래너와 고정 Windows 키 입력 IPC 재사용. 자동 소스·계획 테스트만 수행하며 **실제 앱/Windows 효과는 미검증**.
- **창·데스크톱 전환 코드(빌드 보류):** `window-switch`(다음/이전 창, Alt+Tab/Alt+Shift+Tab), `desktop-switch`(이전/다음 Windows 가상 데스크톱, Ctrl+Win+좌/우)를 별도 D200X 추가 액션으로 구현. 버튼 누름과 노브 회전은 공통 계획 함수를 사용하고 단계량·반전 옵션은 기존 노브 설정을 재사용. 노브 누름으로 선택 확정하는 UI는 아직 없으며 Windows/D200X 실제 실행은 **미검증**.
- **빌드 정책 변경:** 사용자가 주요 변경 전까지 EXE 빌드 보류를 요청하여 `streamdeck-clean-preview.yml`은 `workflow_dispatch` 수동 실행만 허용. 일반 GitHub CI/Node 검사 및 별도 경량 구문 검사는 유지.

## P0~P2 코드 적용 현황 — EXE 보류

- **P0 핵심:** `device-brightness`(장치에서 관측된 값 기준 ±1/2/5/10, 0~100 제한), `system-zoom`(Ctrl+± 및 Ctrl+0 원래 크기), 기존 음량/음소거/스크롤/실행 취소·다시 실행/창·데스크톱 전환을 D200X 별도 액션으로 유지. D200X 실제 밝기 수신이 없으면 추정 값을 보내지 않고 실패 처리.
- **C1 수정:** 구형 페이지마다 서로 다른 **비어 있지 않은** 물리 버튼·노브 할당이 있으면 페이지 범위를 유지. 한 페이지만 설정되고 나머지가 비어 있으면 기존 전역 노브 관례를 유지. 별도 Node 회귀 테스트 완료.
- **P1 일부:** `screenshot`(Win+Shift+S 캡처 UI), `clipboard-edit`(Ctrl+C/V/X), `window-state`(Win+Up/Down), `window-monitor`(Win+Shift+좌/우), `explorer-open`(Win+E), `file-open`/`folder-shortcut`(검증된 Windows 절대 경로로 열기). **출력 장치 선택/마이크 음소거 등은 남음.**
- **P2 일부:** `brush-size`([/]), `timeline-step`(좌/우), `timeline-zoom`(Ctrl+±)은 앱이 해당 키를 지원할 때만 동작. 앱별 확실한 동작/사용자 지정 매핑, 다중 동작 지연/토글/순환은 남음.
- **안정성:** 설정 저장 실패를 사용자 상태에 표시하고, 밝기 값 클램프/5초 keepalive/재연결 페이지 복원 모의 테스트 추가. 실물 USB/Windows 동작을 검증했다고 표시하지 않는다.
- **빌드:** 사용자가 명시적으로 요청할 때만 `streamdeck-clean-preview.yml`을 수동 실행한다. 이번 범위에서 새 EXE/ZIP을 만들지 않았다.

## 통합 이벤트·설정 계약 (설계)

- 입력 어댑터: 물리 버튼 `press/release`, 노브 `press/release/rotate(delta)`. 실제 D200X HID에서 지원된 이벤트만 매핑한다.
- 단일 액션: `{type,settings}`; 버튼에서는 `press`에 실행, 조절형 노브에서는 회전 부호에 따른 `delta` 실행. 조절형 액션을 버튼에 등록하면 증가·감소·토글 중 실행할 연산을 사용자가 선택한다.
- 공통 노브 옵션: 한 칸 변화량 `1/2/5/10`(제한·단위는 대상별 적용), `reverseDirection` boolean, 좌/우 미리보기. 기존 바인딩은 `step=1, reverseDirection=false`로 마이그레이션한다.
- 조절기 확장: `page, volume, zoom`은 기존 코드 경로를 이행; `scroll, brightness, timeline, brush`는 각각 백엔드와 가능 범위를 검증한 후 추가한다.
- 회전의 변화량 적용은 노브가 실제로 보낸 이벤트당 수행한다. 장치 보고서가 전달하지 않는 연속 속도·롱프레스 같은 신호를 추정 생성하지 않는다.
- 앱별 단축키는 프로필/앱 매핑으로 정의하되 안전한 가상 키 allowlist 또는 검증된 입력 엔진으로 전달한다. 사용자 문자열을 셸 명령으로 조합하여 실행하지 않는다.
- `volume/zoom`의 기존 구현은 별도 PowerShell 프로세스 호출을 사용한다. 빠른 회전 부하/메시지 순서/지연 및 Windows GUI·D200X 실기 확인 후 최적화한다.
- `device-brightness`는 `ulanzi-driver`를 통한 장치 실제 밝기 명령을 재사용하고, 기존 keepalive가 보고받은 밝기를 일관되게 유지하는지 검사한다.
