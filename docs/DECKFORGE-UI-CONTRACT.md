# DeckForge 전체 UI·레이아웃 단일 기준

> DeckForge의 사용자 승인 UI가 단일 기준이다. 외부 제품의 화면 관찰은 참고 자료이며 독자 UI 변경 지시가 아니다.
>
> 2026-11-21 사용자 승인 규칙 및 현재 코드 기준의 **화면 보존 계약·문서 목차**. 소스 수정/Windows 빌드/실기 완료 보고가 아니다.
>
> 저장소: SoonCheol/D200X-Deck · 개발 브랜치: codex/streamdeck-761-clean-editor

## 2026-11-21 최종 확정: 속성창 영역 A / B / C / D / F

- **A — 기존 상단 제목·헤더:** 필요한 액션 고유 화면에서만 기존 헤더를 유지하며, 비어 있는 헤더나 불필요한 물음표(`?`) 도움말 버튼을 새로 출력하지 않는다. 오른쪽 목록의 아이콘 설정·플러그인 전용 도움말은 별도 기능이다.
- **B — 누르기 탭 + 취소/저장:** `한 번 / 두 번 / 길게` 3개 탭은 **같은 너비**, 제목·액션 이름 변경 또는 선택 표시에도 폭이 바뀌지 않는다. 탭은 기존보다 **조금 낮게** 만들고 오른쪽 취소·저장 위치를 고정한다. **다른 영역 너비를 결정하지 않는다.**
- **C — 아이콘·미리보기 편집:** **B와 별개인 독립 시각 영역**이다. 왼쪽 기존 상태별 카드 2개(해당할 경우), 오른쪽 98px 미리보기·86px 이미지·실행 테스트를 유지한다. 액션 종류에 따라 내부 편집 항목이 달라져도 **C의 영역 폭·배치 기준·예약 높이는 유지**하여 누르기 탭 전환이 아이콘 카드 크기나 D의 시작 위치를 흔들지 않도록 한다. 상태 2카드가 원래 없는 액션에 가짜 카드를 만들지 않는다.
- **D — 단일 액션 설정 부모 영역:** 이전 그림의 **D와 E는 별개 상위 영역이 아니다.** 모두 **D 안의 하위 그룹**이다. `D-1 옵션`과 `D-2 액션별 상세 필드`를 필요에 따라 표시한다. 한 번에 선택된 누르기 액션 하나의 필드만 보여주고, 다른 B/C 영역 크기·위치에 영향을 주지 않는다.
- **F — 속성창 전체 외곽:** 메인 화면의 기존 영역 배치/스크롤·노브·측면 버튼·와이드 화면·특수 액션 편집기와 격리한다. B/C/D의 국소 변경을 다른 화면에 일반화하지 않는다.
- **공통 드래그 계약:** 오른쪽 기본 액션과 플러그인 목록을 **클릭만으로 등록하지 않는다**. 일반 LCD 버튼에 드롭하면 3누르기 선택 영역, 속성창의 **누르기 탭에 직접 드롭하면 그 탭**, 속성창의 **그 밖의 빈·시각·설정 영역에 드롭하면 현재 선택된 누르기**에 등록한다. 이미 등록된 동작을 교체할 때 기존 확인창 및 특수 액션 제한 유지.
- **변경 검증:** 선택된 액션 이름의 길이가 달라져도 B의 세 탭과 취소/저장의 X좌표, C의 아이콘·미리보기 기본 크기, D의 시작점이 유지되는지 확인한다. 사용자 실기 검증 전에는 확정 완료라고 쓰지 않는다.

## 1. 필독과 기준 우선순위

- 일반 개발 세션에서는 **AGENTS.md + docs/D200X-CURRENT-STATUS.md** 두 문서만 기본 확인한다. **화면·레이아웃을 다룰 때** 이 문서의 필요한 부분과 해당 editor.js/style.css만 추가 확인한다.
- 가장 최근의 **사용자 승인 사항은 목표 규칙**, 최신 브랜치의 **실제 소스는 구현 현황**이다. 문서의 과거 레이아웃과 코드가 다르면 둘을 구분한다. 구현되지 않은 목표를 이미 완성되었다고 적지 않는다.
- 오래된 보관 문서·예전 HTML 시안은 이력과 참고 자료이지 최신 레이아웃을 덮어쓰는 기준이 아니다.
- 사용자가 승인한 디자인을 임의 재설계하거나 카드를 새로 그리지 않는다. **기존 UI 컴포넌트 재사용, 요청 범위만 국소 수정**이 원칙이다.
- 신규 기능 우선순위 확인 시에만 docs/DECKFORGE-ROADMAP.md를 읽는다. 기존 정상 기능의 전수 재조사 금지.

## 공통 버튼 클릭 영역·여백 규격 (2026-11-24 사용자 승인)

- 버튼·탭처럼 테두리/배경으로 하나의 조작 영역을 표시하는 내장 UI는 **텍스트뿐 아니라 표시된 사각 영역 전체**에서 같은 동작을 한 번 실행한다. 빈 여백·아이콘·부제도 포함한다. 실제 독립 체크/삭제/메뉴 등 별도 조작은 그 고유 동작만 수행하며 부모 클릭과 중복 실행하지 않는다. 비활성·키보드·포커스·드래그 의미는 보존한다.
- 체크박스/체크서클과 아이콘은 버튼 또는 카드 경계선에 밀착시키지 않는다. 기존 텍스트의 위치·정렬·글꼴·버튼 외곽 치수는 유지하면서 내부에 균형 있는 여백을 확보한다. 일반 누르기 탭의 체크서클은 왼쪽 바깥 경계에서 약 8px를 목표로 하며, 다른 컴포넌트는 기존 크기에 맞춰 적절한 여백을 적용한다. 일률적인 폭 확대나 텍스트 이동 금지.
- 신규 UI 및 기존 UI 수정 시 위 규격을 적용하고 실제 클릭 가능한 범위와 독립 조작 충돌을 확인한다. 플러그인 외부 원본 UI 및 단순 표시 영역에는 강제 클릭을 추가하지 않는다. 전체 기존 화면의 확인은 별도이며 문서만으로 전수 적용 완료라고 하지 않는다.

### 아이콘 편집 팝오버 위치 (2026-11-24 사용자 승인)

- Fusion 명령 관리자 버튼/페이지 슬롯 및 DeckForge 버튼은 hover 시 로컬 명령 ID 설명을 표시한다. 조회는 캐시 전용(오프라인 지원, 없는 설명은 미수집 표시), 텍스트 렌더링, 포인터 이동 시 늦은 응답 무시. 명령 관리자 ⓘ 상세의 메뉴·툴바 경로는 제거하고 명령 설명으로 교체한다.
- Fusion 명령 버튼은 DeckForge 자체 명령 속성창(기본 폭 360px, Key Up 카드 우측 +8px/상단)을 사용한다. 창 제목은 Fusion 명령 속성, 본문은 현재 원본 아이콘(캐시가 있을 때), 한글/영문 명령명, ID, 실제 브리지 툴팁(개별 조회 시 로컬 캐시, 없으면 미확인)만 표시한다. 검색/상태/적용/취소 없음, X로 닫기. 명령 변경은 명령 관리자 사용. Run Command 직접 등록 항목 숨김, Fusion 명령 관리자 유지. 기존 외부 실행 플러그인/등록 ID 보존.
- Key Up/Key Down 등 좌우 상태 카드의 배경색 팔레트, 글자 속성, 아이콘 라이브러리, 특수문자 등 카드 조작으로 여는 DeckForge 자체 팝업은 클릭한 카드의 **아이콘 창 전체(상태 카드)의 오른쪽 외곽 테두리 + 8px**를 가로 기준으로 하고, **해당 상태 카드의 최상단 외곽 테두리**를 세로 기준으로 한다. 이미지 자체의 오른쪽/상단 경계나 전체 속성 영역 오른쪽을 기준으로 하지 않는다. 두 카드에 동일한 규칙을 독립 적용한다.
- 화면 공간이 부족할 때만 내부 스크롤 및 화면 내 배치 예외를 적용한다. 기존 카드 크기/텍스트/설정 의미 및 중첩 글자 색상 팔레트의 기존 동작 유지. 자체 창은 기존 크기를 우선하며 우측 공간이 부족할 때만 폭/높이를 조정하거나 화면 내 대체 배치를 사용한다. Windows 파일 선택 및 기타 OS 대화상자는 이 규격 적용 제외. 클립보드 및 초기화의 기존 즉시 동작은 그대로 유지.
- **물리 버튼 단위 편집 세션:** 동일 버튼의 한 번/두 번/길게 누르기, Key Up/Down·OFF/ON, 글꼴/배경색/체크/입력·아이콘 라이브러리·특수문자 등 자체 편집창, 일반 누르기 액션의 등록·교체·삭제, 동일 노브의 내부 제스처 편집은 하나의 미저장 초안으로 유지한다. 내부 전환에서 저장/이동 경고·자동 확정·초안 초기화를 하지 않는다. 명시적 저장은 전체 초안을 한 번 확정, 취소는 전체 초안을 복원한다. 기존 외부 SDK PI의 별도 저장, 전역 아이콘팩 삭제·전역 관리·특수 액션 등록 계약은 유지한다. 실제 다른 물리 버튼·페이지·프로필로 이동할 때만 기존 미저장 보호 적용.

## 페이지 번호 버튼 전용 고정 탐색 계약 (2026-11-22)

- 기존 페이지 표시 **번호·디자인·아이콘 편집·자동 추가·모든 페이지 일괄 적용**은 그대로 유지한다.
- 페이지 표시 버튼 자체는 **한 번 누르기: 홈**, **두 번 누르기: 직전 페이지**, **길게 누르기: 직전 프로필**을 전용 고정 동작으로 사용한다.
- 이 세 동작은 페이지 번호 **전용 속성창에 읽기 전용으로 표시**, 임의의 다른 액션 할당·선택지 변경은 제공하지 않는다. 이전 프로필은 기존 방문 이력으로 A↔B 왕복 가능하다.
- 기존 프로필의 옛 `indicatorDown/indicatorHold` 설정은 삭제하지 않고 보존하되, 페이지 번호 버튼의 실제 탐색 동작에서는 고정 매핑이 우선한다.
- 기존 와이드키의 덱폴더 상위 한 단계 복귀, 측면 버튼·노브·Key Logic·순차 동작의 입력 판정은 변경하지 않는다.

## 3. 일반 LCD 버튼 속성창 — 확정한 목표 레이아웃

### 3.1 탭·상단 툴바

1. **아이콘 창 바로 위 한 줄**: 왼쪽에 **한 번 누르기 / 두 번 누르기 / 길게 누르기** 탭 3개, 오른쪽에 **취소 / 저장**.
2. 탭 내부에는 **사용 체크서클(원형 체크박스)·누르기 이름·등록된 액션 이름만**. 원형 체크는 탭 왼쪽 경계선과 약 8px 여백을 유지한다. 내장 속성창/배경색 팔레트의 체크박스도 원형 표시로 통일하되 실제 체크박스 의미·키보드·비활성 동작과 라디오 버튼은 유지한다. 탭의 큰 액션 아이콘·1/2/3 숫자·대표 마커를 표시하지 않는다.
3. 하나의 일반 LCD 버튼에 누르기 종류별 **서로 다른 액션 하나씩**을 등록한다. 버튼 선택 시 **한 번 누르기** 탭이 기본이다.
4. 탭을 바꾸면 **선택된 액션의 기존 전체 속성창 하나만** 전환한다: 아이콘 카드, 제목·스타일, 미리보기 및 액션별 모든 설정. 다른 두 액션의 설정을 지우거나 덮어쓰지 않는다.
5. 사용 체크 해제는 그 누르기 실행만 비활성화하고 설정을 보존한다. 선택한 탭의 액션만 개별 삭제한다.
6. **의미 없는 액션 경로줄(기본 액션 › 분류 › 액션명)과 별도의 장식용 제목줄 추가 금지.** 상단 왼쪽의 불필요한 **? 도움말 버튼은 제거**하고 기존 실행 테스트와 플러그인 전용 도움말은 유지한다.
7. 일반 액션을 버튼에 드래그하면 **3갈래 임시 누르기 드롭 선택 영역**을 보여준다. 이 영역에서는 등록된 액션의 아이콘·이름 표시를 유지한다. **속성창 탭의 아이콘 금지**와 혼동하지 않는다.
8. 폴더·페이지 표시·Key Logic·순차/무작위 복합·SDK 등 특수 액션은 기존 전용 경로 유지.

### 3.2 아이콘 2장과 미리보기

- **좌측 상태별 아이콘 카드 2개 → 우측 미리보기**의 한 줄 배치. 왼쪽 미리보기로 뒤집지 않는다. 최신 style.css 1.1.90 이후 구조를 우선한다.
- 카드 2장은 **가변 폭**, 카드 간 **12px**. 이미지 **정사각형(1:1)**, 비율 왜곡 없음. 과거 **196px 카드×2 / 이미지 84px** 고정 수치를 현행 가변 카드에 강제 적용하지 않는다.
- 각 상태 카드 순서: **상태명**, **표시 체크·제목 입력·T⌄ 글꼴 설정**, 아래 **왼쪽 아이콘 이미지 + 오른쪽 세로 5개 버튼**.
- 5개 버튼: **라이브러리 / 파일 / 클립보드 / 특수문자 / 초기화**. 각 **76×25px**, 세로 간격 **4px**, 기존 색상·테두리·Pretendard 글꼴·기능 유지.
- **미리보기 카드 너비 98px, 내부 미리보기 이미지 86×86px**, 아래 **▶ 실행 테스트**. 미리보기 자체와 실행 테스트를 생략하거나 임의의 곳으로 옮기지 않는다.
- HA 센서 표시를 제외한 두 카드가 없는 단일 이미지·전용 액션에 가짜 상태 카드를 만들지 않는다. 그 액션의 기존 단일 미리보기/속성을 그대로 사용한다. HA 센서 표시(states:1)는 기존 Key Up/Key Down 두 카드 레이아웃을 유지하되 Key Up만 편집 가능, Key Down은 비활성 표시 전용(두 번째 상태 저장 없음), 오른쪽 기존 미리보기/실행 테스트 유지. 센서 설정창은 첫 카드 오른쪽 외곽 +8px 및 상단에 정렬(화면 공간 부족 시 뷰포트 보호); 기존 선택 표시 속성은 단일 설정으로 이관하고 이전 상태 데이터는 보존한다. HA 제어(states:2)는 기존 두 카드 유지. HA 센서의 고정 합성 순서(하→상): 단추 배경색 → 사용자 지정 이미지 → 투명 실시간 센서명·측정값 → 제목 텍스트. 사용자 이미지가 실시간 센서를 대체하거나 가리지 않으며 미리보기·메인 키·실기 PNG가 공통 합성기 및 실시간 레이어 캐시 키를 사용한다. 동적 복수 선택 항목은 선택 순서 목록과 위/아래 이동으로 명시적으로 재정렬할 수 있으며 배열 순서는 동시 표시의 상→하 및 순차 표시의 순서를 결정한다. 적용 후 일반 저장/취소 규칙 유지.
- 제목·이미지·배경의 **표시 속성 선택** 체크 규칙, 양 상태 독립·공유, 실제 이름 규칙 ON/OFF 이미지 쌍 예외 및 원본 값 보존은 **D200X-CURRENT-STATUS.md §3.1** 우선.
- 과거 ‘실행 테스트는 action-head에만’/‘취소·저장은 무조건 맨 아래’라는 일반 규칙보다 **현행 상태 카드 UI와 이번 상단 툴바 사용자 승인**이 우선한다.

### 3.3 번호·대표 이미지

- 누르기 번호 **1·2·3은 상단 아이콘 카드(2장 없는 경우 미리보기) 및 D200X 버튼 그리드 대표 이미지의 왼쪽 위 오버레이**로 표시. 탭 안에 번호를 붙이지 않는다.
- 대표 아이콘 선택은 **왼쪽 위 번호 버튼 자체**를 클릭하여 지정. 별도 체크 마커 제거. 두 상태 카드의 번호 동일 적용. 현재 대표 밝은 파랑, 비대표 회색, 저장된 대표가 비활성으로 대체 표시되는 경우 황갈색(툴팁으로도 구분). 기본은 **한 번 누르기**.
- 선택 대표가 비활성화되면 **활성화된 한 번 → 두 번 → 길게 누르기** 순으로 대체하되, 사용자의 저장된 대표 선택은 유지한다.
- 이 번호와 대표 마커는 **편집기 전용 오버레이**. 물리 D200X에 전송하는 PNG에 합성 금지.
- 실제 배지 위치·표시 기능은 최신 소스와 비교해 검증할 대상이며 **문서 작성으로 수정 완료를 주장하지 않는다**.

### 3.4 액션 고유 설정

- **효과음 재생 한정:** 파일 선택 아래에 `동작 / 페이드 / 페이드 시간` 한 줄, 다음 줄 `출력 / 음량`을 배치한다. 음량 슬라이더는 해당 액션의 재생 음량 0~100을 제어하며, 재생 중인 효과음에 미리 적용한 값은 저장/취소에 연동한다. 다른 액션 레이아웃에는 적용하지 않는다.

- 단축키 전환·프로그램 열기·페이지 선택 등 탭별 액션의 **기존 전체 필드**를 그대로 보여준다.
- 프리셋, 단축키 키보드/선택 입력, 경로 선택 버튼, 힌트, 제목 스타일, 저장/취소 등 기존 처리·너비·정렬 임의 생략/재설계 금지.
- 선택된 탭 아래의 아이콘·미리보기·제목·필드·상태 UI를 **같은 액션 기준으로 함께 변경**한다.

## 6. 앞으로의 문서·개발 작업 규칙

1. 새 채팅에서 사용자가 레이아웃을 다시 설명하게 하지 않는다. 기본 2문서 확인 후 **UI 작업이면 본 문서 해당 절만 추가 확인**한다.
2. 시안은 **최신 소스의 실제 카드와 미리보기 위치·크기·옵션**을 재사용한다. 다른 카드/가짜 필드·제목줄·구분선을 임의로 추가하지 않는다.
3. 수정 전 **보존할 영역, 바꿀 영역, 기존 코드와 승인 목표의 차이**를 구분한다. 불명확한 부분을 추측해 구현하지 않는다.
4. 승인된 작업 외의 소스 수정·커밋·빌드·브랜치 전환/생성·PR 병합 금지. 기존 데이터와 작동 기능 보호.
5. 확정된 UI 변경 시 **이 문서의 해당 절**, 구현·검증 상태가 바뀌면 **D200X-CURRENT-STATUS.md**의 최신 스냅샷을 교체한다. 과거 이력은 보존한다.
6. **소스 점검 / 자동 검사·CI / Windows 빌드 / 실제 Windows·D200X 검증**을 각각 별도로 보고한다. 문서 정리를 기능 완성으로 표기하지 않는다.

## 7. 상태 카드 및 기본 골격의 세부 계약 기본 골격·상태별 카드 (최신 예외 우선)

**기본 UI 고정**: 왼쪽 D200X 일반 키 13개·와이드 1개, 측면 버튼 2개, 노브 3개와 페이지 제어; 아래 인스펙터; 오른쪽 프로필·장치·설정·검색·기본 액션/플러그인 영역. 외부 앱 인스펙터/UI로 대체하거나 임의 재배치·폰트/버튼 높이 재설계 금지. 변경은 사용자 요청된 국소 범위만.

**기존 일반 키 인스펙터의 4영역 기본 원칙**(상태 카드가 없는 액션 등에 적용):
1. `.action-head`: 액션 경로·이름·도움말, 오른쪽 **▶ 실행 테스트**.
2. `.properties`: 대표 미리보기, 제목 및 전체 액션별 설정(복합 액션 포함). 동적 속성 완성 후 아이콘 영역 생성.
3. 아이콘 한 쌍: 일반/Fusion `Key Up → Key Down`, 실제 상태형 SDK `OFF → ON` 중 한 종류만; 저장한 반대 스키마의 값은 삭제 금지.
4. `.inspector-save-bar`: 기본은 하단 **취소 / 저장**. 대표 아이콘·제목·필드 값을 같은 시작선에 맞추고 숨겨진 필드 삭제·잘라내기 금지.

**2026-11-17 최종 승인 예외 — 상태별 독립 제목 카드가 실제 표시되는 일반 키**: 위 고정 196px 카드/4영역 규칙보다 **아래 사항 우선**.
- `.state-title-layout`은 최신 소스의 **왼쪽 OFF/ON 또는 Key Up/Down 가변 카드 2장 → 오른쪽 대표 미리보기(카드 너비 98px, 내부 이미지 86×86px)** 순서로 한 가로줄에 배치, 카드 간격 **12px**, 이미지는 정사각형 `aspect-ratio:1/1`, 공간에 맞게 자동 축소하되 비율 왜곡 금지. 과거 미리보기 왼쪽 서술은 최신 구현/사용자 승인에 우선하지 않음. 창 크기에 따른 양방향 스크롤/클리핑 여부는 GUI 실측 대기.
- 각 카드 **상태명 바로 아래**에 표시 속성 선택 체크박스(기존 제목 체크박스)·입력 placeholder `제목`·`T⌄` 글꼴 속성 버튼. 별도 ‘제목’ 라벨 없음. 위치와 크기는 유지하며 의미는 아래 §7.1 최신 계약을 따른다.
- 기존 1.1.4 제목 전용 구현: 제목 1/2의 텍스트·활성화·글꼴·크기·색·외곽선·정렬을 저장하고 체크 조합에 따라 공유. 실제 사용에서 공유 요구와 불일치 확인. **후속 구현은 §7.1 최신 계약으로 확장**하고 제목만 공유하는 옛 정책을 적용하지 않는다. 해제 시 기존 설정값 보존, 과거 항목 fallback, 실제 편집 시에만 설정 생성 및 dirty 갱신 규칙 유지.
- 스타일 프리셋은 양쪽 모두 기존 단일 전역 `deckforge-title-style-presets-v1` 공유. 같은 `T⌄` 재클릭 닫기, 다른 카드/바깥 클릭 시 `aria-expanded=false`. 각 상태 카드의 이미지 미리보기 역시 실제 D200X 합성기와 같은 제목·스타일 사용.
- 각 카드의 기존 **라이브러리/파일/클립보드/특수문자/초기화** 버튼 **76×25px**, 간격 **4px** 고정; Pretendard 기본 크기 보존.
- 상단 **▶ 실행 테스트** 위치 유지. **플러그인 속성 열기**는 상태 카드 위 왼쪽, **취소/저장**은 같은 툴바 오른쪽. **이 경우 하단 저장 바 위치 규칙 적용하지 않음.**
- 이전 고정 계약은 카드 한 쌍 196px×2+12px=404px, 이미지 84px, 값 시작선 196px 및 `--inspector-preview-width:98px`를 정의했지만 **최신 가변 상태 카드 예외에 우선하지 않는다**. 예외 외 일반 액션/노브/측면 버튼/와이드는 기존 구조 유지.
- 공통 체크박스 15×15px 및 값 열 정렬, 폴더 자동 종료 시간의 별도 필드/숫자 내부 ‘초’, 웹사이트 프로토콜(기본 `http://`, 체크 시 `https://`), 프로그램 실행 인수 독립 전달, Windows EXE/LNK/BAT/CMD 드롭 시 응용 프로그램 등록·아이콘/제목 자동 추출은 기존 동작 보존.

### 7.1 최신 승인 개발 계약 — 표시 속성 선택 체크박스 (2026-11-18, 1.1.5 코드 반영·실기 대기)

**정확한 의미:** 기존 카드의 '제목 체크박스'는 제목 표시만이 아닌 **버튼 표시 속성 선택 체크박스**이다. Key Up/Key Down 및 OFF/ON 카드에 동일한 규칙을 적용한다. 기존 레이아웃·체크박스 위치·크기는 보존한다.

공유 대상 전체:
- 일반 아이콘 이미지(라이브러리/파일/클립보드/특수문자 등 기존 등록 경로). **ON/OFF 이름 규칙으로 등록된 실제 상태 이미지 쌍만 예외:** 각 상태의 고유 그림을 유지한다.
- 아이콘 배경색(단추 자체 배경색) 및 활성화 여부.
- 제목 텍스트, 글꼴·크기·굵기·기울임·밑줄·정렬, 글자 색상·외곽선 색상/두께 등 기존 제목 스타일 전체.
- 제목 배경 활성화 여부·색상·불투명도. 기존 라운드 자동 크기 및 `<br>` 합성 유지.

**보존 조건:** 체크 해제 및 공유 적용은 출력 결정에만 영향을 준다. 반대쪽 이미지·배경·제목·스타일 설정들을 덮어쓰거나 초기화하지 않는다. 다시 체크하면 원래 독립 설정이 복원되어야 한다. ON/OFF 이름 규칙의 기존 자동 페어링 동작을 보존하며 실제 페어 등록 여부를 근거로 예외 판정한다. 단순히 HA/SDK라는 이유만으로 모든 이미지에 예외 적용 금지. 기존 파일/프로필/아이콘팩 원본을 수정하지 않는다. 구형 데이터는 동일 팩 ID만으로 페어로 추측하지 않으며, 실제 이름 규칙 및 두 래스터 이미지 일치 확인으로 판정한다. 신규 자동 등록은 페어 식별자를 함께 저장한다. 사용자 설정이 없는 SDK 기본/실시간 이미지는 상태 표시 계약을 보호한다.

**구현 검증 범위:** 대표 미리보기, 양쪽 상태 카드, 메인 버튼 및 실제 D200X PNG가 같은 표시 속성 결정 규칙을 사용하도록 관련 경로 확인. 체크 4조합, 일반 이미지와 실제 ON/OFF 페어 예외, 모든 표시 속성 공유, 재체크 복원, 저장/취소·재실행·기존 프로필 보존을 집중 검증. 상태형 액션 실행 상태/순간형 물리 입력의 기존 계약은 유지. 1.1.4에서 정상 확인된 최초 제목 표시, 배경 기능, 색상 우클릭 삭제, 팔레트 및 강제 줄바꿈 회귀 금지. 1.1.5에서 구현 및 자동 Windows 빌드 대상; 실제 GUI와 물리 D200X 검증 대기.

## 8. Key Up/Down·상태형 아이콘의 예외 정책

- **일반 순간형과 모든 Autodesk Fusion 명령**: `Key Up` 기본, 물리 `Key Down` 누름 이미지. 놓으면 복귀. 이미지가 같으면 기존 축소 효과만 적용하며 이중 효과 금지. 속성창 미리보기 마우스 클릭은 **시각 시뮬레이션 전용**; HA 토글·명령·SDK `keyDown` 전송 금지.
- **실제 상태형**(HA ON/OFF, SDK `setState/setImage`, `multi-switch`): 상태 우선, Key Up에 OFF/기본 강제 복귀 금지. Fusion 전체 명령은 사용자 지정 무상태 예외. 일반 SDK 전체를 무조건 상태형 취급하지 않는다.
- **표시 전용** `indicator`, **와이드 특수 화면**은 일반 키 두 상태 이미지 정책 제외. `timer`는 카운트다운/문구, `logic`은 실제 Down/Up 판정, `open-app`의 hold(close/force)는 누름 시간을 보존. `hotkey-switch`의 내부 교대 상태 표시 정책은 후속 설계.
- **페이지·프로필·폴더 변경**(`previous/next/goto/profile/folder`)은 전환 뒤 새 화면 슬롯의 정상 이미지가 우선, 이전 눌림 상태 잔류 금지. `sleep`은 잠자기/깨우기 동작 우선.
- `multi`/`random` 등 일반 액션은 순간형 가능. `system-mute`나 `media`가 토글 명령이라는 이유만으로 실제 장치 상태를 추적한다고 가정하지 않는다. 노브 회전에 키 Up/Down 이미지를 임의 적용하지 않는다.
- **정책과 구현/실기 증거를 구분**. 예외 문서의 과거 “구현 전” 체크박스는 당시 스냅샷이다. 최근 Key Up/Down 카드 기능 코드·Windows 빌드 성공 기록은 본 문서에서 판단하되 물리 동작은 별도 확인한다.

- Fusion Run Command 일반 LCD 키: `길게 누르기 : ESC` 기본 체크, 해제 시 기존 SDK 이벤트 유지. 체크 시 600ms 미만은 명령 실행, 길게 누르면 명령 없이 활성 Fusion에 ESC 1회 요청. 실기 확인 별도.
