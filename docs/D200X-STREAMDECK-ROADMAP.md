## 2026-11-14 실행 테스트·밝기 보호·원본 액션 확장 (코드 단계)

- **안전:** `transport.cjs`의 D200X 버튼/노브 상대 밝기를 **20~100%**로 제한하고, 원본 `brightness` 고정값(최소/낮음/중간/높음/최대)을 20/30/50/75/100%로 연결했다. **20% 실제 시인성은 장치 실측 전 미확인.** 이미 20% 미만인 기기 값을 단순 keepalive가 그대로 유지하는 기존 정책은 별개다.
- **미리 실행:** 버튼 선택 후 `▶ 실행 테스트` / 노브 왼쪽·오른쪽·누름 테스트를 기존 물리 이벤트와 동일한 `DeckCore.previewHardwareEvent` 어댑터로 실행. **PC 편집창이 활성화되면 Ctrl+Z 등 전경 앱 대상 키가 편집기 쪽으로 갈 수 있으므로 실제 앱 결과는 실기 검사 필요.** 단축키·텍스트·파일 닫기 같은 영향 있는 동작은 사용자가 버튼을 명시적으로 눌렀을 때만 실행한다.
- **파일 선택 UI:** 물리 버튼/노브 속성에서도 파일/폴더 선택기를 연결한다. 기존 14개 키의 클릭은 여전히 편집용이다.
- **원본 24개 중 새로 연결한 실행 경로:** `brightness`, `media`, `hotkey`, `hotkey-switch`(실행 중 메모리 토글), `open`, `open-app`(실행만), `close`(선택한 .exe와 같은 경로만; 강제 종료 옵션), `timer`(시작/다시 누르면 취소·상태 알림), `text`(유니코드 직접 입력), `audio-play`/`audio-stop`(Electron HTMLAudio, 재생·중단·반복·오버랩 기본), `website`의 GET 모드. 이전 페이지/다음 페이지/페이지 지정/표시 및 웹사이트 기본 브라우저 실행은 기존 구현을 보존한다.
- **부분 구현 명시:** `timer`의 사운드 알림·화면 카운트다운, `text`의 진정한 클립보드 붙여넣기 모드(현재 클립보드를 바꾸지 않고 Unicode 직접 입력), `audio-play`의 페이드·출력장치, `open-app`의 길게 누르기 옵션, `website`의 브라우저 직접 선택은 미구현. 실기 재생 호환성/Windows Unicode SendInput/C# 컴파일 여부는 아직 검증되지 않았다.

## 제품 정의 — 변경 금지

- **원본 UI/UX:** Stream Deck **7.6.1 (23033) 한국어 Windows**.
- **기기:** Ulanzi D200X. 일반 키 13개 + 와이드 키 1개, 측면 버튼 2개, 노브 3개.
- **기존 Ulanzi Deck 재사용:** USB/HID 통신·기기 입력·프레임/이미지 전송 코드만. 기존 UI, 속성 편집기, 등록·실행 구조는 가져오지 않는다.
- **플러그인 시스템:** 현재 범위 밖. 기본 제공 24개 키 액션에 집중. 사용자와의 후속 방향 합의: **Ulanzi 플러그인을 우선 지원**, Stream Deck 플러그인 변환기(변환 불가 이유 진단 포함)는 별도 후속/번외. 현재 변환기 구현 시작하지 않음.
- **우선순위:** 정상 작동과 원본 조작 흐름 → 정확한 속성창/우클릭 메뉴 → 원본과의 크기·아이콘 비교.
- 모든 설정값은 저장·재실행·기기 조작에 실제 반영되어야 한다. 단순히 폼이 보이는 것으로 완료 처리하지 않는다.

## 아키텍처 / 모듈 간 계약

```text
editor-ui (Stream Deck식 UI, Electron renderer)
  └── deck-core (프로필·페이지·폴더·24개 액션 설정/실행·이벤트)
        └── ulanzi-driver (D200X HID 통신 전용)
```

1. **`ulanzi-driver`**: `connect/disconnect`, `onKeyEvent`, `onKnobEvent`, `sendKeyImage`, `sendPage`, `getDeviceStatus`를 기능 계약으로 정의한다. 기존 `app/lib/deck.js`, `app/lib/protocol.js`, `app/lib/page.js`를 후보 근거로 사용한다. 함수명은 제안이며 **현재 코드의 확정 API가 아니다**. 지원 범위·인덱스는 실제 D200X 통신 자료로 검증.
2. **`deck-core`**: `profileId / pageId / slotId / actionId / actionType / settings`를 정의한 스키마와 저장·마이그레이션 계약, `assignAction`, `updateActionSettings`, `deleteAction`, `switchPage`, `executeAction`을 기능 계약으로 확정한다. UI와 USB API에 직접 의존하지 않는다. 원본 내부 JSON 포맷과 같을 필요는 없지만 편집 및 복원 동작은 일치해야 한다.
3. **`editor-ui`**: 사용자 액션 등록/속성 변경을 `deck-core`에 요청하고, 코어의 상태 이벤트로 버튼/노브/속성창 표시를 갱신한다. **Ulanzi Deck의 기존 renderer/inspector는 사용하지 않는다.**
4. **연결 흐름**: 아이콘/제목 변경 → 코어 저장 → 지정 슬롯 렌더링 → 드라이버 이미지 전송. 기기 버튼/노브 이벤트 → 코어 활성 프로필·페이지의 대상 슬롯 조회 → 액션 실행. 페이지/폴더 전환은 전체 슬롯 렌더링 및 전송.

**구현 전 결정할 세부 규격:** 와이드 키 및 측면 버튼·노브 인덱스/이벤트 종류, 이미지 포맷·해상도, 디바이스 경합/재연결, 설정 직렬화, 실행 실패 표시. 기존 소스로 확인되지 않은 값은 채워 넣지 않는다.
