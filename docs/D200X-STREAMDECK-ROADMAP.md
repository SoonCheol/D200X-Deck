# DeckForge 잔여 개발·검증 로드맵
> 2026-11-24 · SDK 재설계 기준 승인. 상태는 CURRENT-STATUS, 기술 규격은 DECKFORGE-SDK-1.0. 아래는 미완료 목표이며 구현 착수 여부는 사용자 지시로 결정.

## SDK 1.0 재설계 순서

| 단계 | 범위 및 통과 기준 | 롤백 |
|---|---|---|
| 01 | 검증 기준선: 보고서의 CI 누락 4개/실패 2개 및 전체 44개 테스트 인벤토리 직접 확인. 의미 있는 검사 유지, 누락 없는 CI 및 전수 통과 | 검사 변경만 되돌림; 실패 시 다음 단계 금지 |
| 02 | sd-plugin instanceId/실행 세대: 19개 생성·복제·이동·복원 경로 확인 및 중복/마이그레이션/기존 프로필 보존 검사 | 기존 라우팅 유지/복귀, 원본 데이터 보존 |
| 03 | 공통 합성기: 캐시, pageEpoch/slotRevision, dirty loop, 기존 DOM 유지·깜박임/경쟁 검사, 미리보기 정책 보존 | 기존 합성/전송 경로 복귀 |
| 04A | Model 2: service/button 실행 환경 분리 및 재사용, 기존 API/권한/수명/큐 회귀 및 실제 프로세스 검사 | legacy runner |
| 04B | Model 5: CSP 실행 가능성 검증, Worker/DrawOps, watchdog, 보안/장애 주입, 서비스 PID 격리·버튼 OOM 영향 검증 | Model 2/legacy 유지. 미통과 시 기본 전환 금지 |
| 05 | 설정 저장: requestId/revision/세대/결과 일관성, 응답 유실/ABA/저장 장애·이동/재시작, 기존 1효과 제약 및 선택적 결과 이벤트 | 이전 저장 경로, 확정 데이터 유지 |
| 06 | 범용 네트워크·공유 상태: 오류 전달, 세대/갭 복구, HA 카탈로그·delta·삭제·stale·조건부 tick. 제어 재실행 금지 | 검증된 이전 네트워크/플러그인 |
| 07 | 선언형 범용 속성창/제목, 기존 UI 보존 및 HA 예외 제거, 비HA 예제 코어 변경 없이 검증 | 호환 속성 렌더러 |
| 08 | 플러그인 관리: keepData/purge, 의존성·누락·재설치·선택 복원/신뢰·DPAPI 보호 | 관리 기능 비활성, 원본 보존 |
| 09 | USB 개별 키: 기본 OFF, 전체 PAGE 캐시, 실기 전송/와이드/재연결 검증; 통합 안정성 검사 | 즉시 PAGE 전체 전송 |
| 10 | SDK 1.0 출시 판정: 전체 회귀, Windows 통합/보안/soak 실측, 실제 HA/D200X/절전·재연결. 미검증 기능 완료 선언 금지 | 출시 보류, 검증된 단계 유지 |

단계 의존성: 01→02→03→04A→04B→05→06→07→08→09→10. 04B 보안 검증이 지연되면 Model 2의 안전성이 입증된 범위에서 05 이후 진행 가능하나 최종 엔진 판정은 별도. 09는 실기 전 기본 OFF. 설정 저장과 USB 출력의 실제 성공 여부를 별도 검증. 수정 단위 집중 검사, 단계 완료 시 관련 회귀, 최종 단계 장시간 통합 검사. 보안/데이터/기존 기능 회귀 발견 즉시 중단. 임의 성능 수치 대신 측정 기준선 사용.
