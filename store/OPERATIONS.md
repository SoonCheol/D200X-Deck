# DeckForge Store operations

## Backup and recovery
Backup contains sensitive accounts, sessions, SQLite and immutable blobs. Restrict access to the owner; do not commit or share archives. Stop only the Store container and verify stopped state before copying the entire /data volume including SQLite WAL/SHM files if present. Never copy only the live SQLite file. Use a separate protected backup location, preserve numeric UID/GID and mode, compute archive SHA256, then restart the original service in a finally/cleanup path. Confirm health. Never delete the original volume.

Restore first to a new isolated volume, not the live volume. Check archive SHA256 before extraction, reject unexpected paths, symlinks and nonregular objects, preserve UID 10001 access. Use the same verified image, no network and read-only mount for verification where SQLite permits; a writable isolated copy is acceptable for WAL recovery. Run `python verify_data.py /data` against the restored copy, require exit 0 and ok=true. Verify database integrity, foreign keys, current pointers, release metadata and all referenced blob hashes. Unreferenced blobs are not garbage-collected. Start a separate isolated test instance using the original origin configuration without public DNS/proxy and test owner login, catalog and sample hashes. Restored sessions are sensitive: revoke all restored sessions before switching to production, by an explicit offline SQLite transaction `DELETE FROM sessions;` on the restored copy while stopped (never mutate original backup). Keep the previous production volume intact; switch only on explicit recovery approval. Store private signing key outside NAS and back up independently. No unattended restore or deletion.

## Updates
Record current image ID and verified archive, stop/store backup, verify new artifact, import and update only the Store stack while preserving its volume, check health and HTTPS. Rollback image and, if schema/data changes require it, restore a separately verified backup with explicit approval. Keep current and last known-good image. No automatic prune or broad Docker cleanup. Monitor disk space, failed logins, audit entries and backup hashes. The application limits login attempts, uploads and SVG conversion; proxy and NAS monitoring remain required. Restrict administrative uploads to trusted owner. SVG child is not a full filesystem/network sandbox; no untrusted administrator access. Python versions and base digest are pinned but wheel hashes, apt snapshot and independent vulnerability scan remain future hardening.
